# brainstorming

Transform ideas into validated designs before any implementation begins.

## Core Rule

**Hard gate**: No coding, scaffolding, or implementation until a design has been presented and explicitly approved by the user. "Simple projects are where unexamined assumptions cause the most wasted work."

## 9-Step Process

1. **Explore project context** — review existing files and documentation
2. **Offer visual companion** — propose mockups or diagrams if helpful
3. **Ask clarifying questions** — one at a time, never multiple at once
4. **Propose 2-3 approaches** — with documented trade-offs for each
5. **Present design** — in sections scaled to complexity (sentences to 300 words)
6. **Write design documentation** — save to specs directory
7. **Self-review the spec** — check for placeholders, contradictions, ambiguity
8. **Request user review** — of the written specification
9. **Transition to implementation** — invoke the `writing-plans` skill

## Constraints

- One question per message — avoid overwhelming users
- Prefer multiple-choice options over open-ended questions
- Request approval after each design section
- Only invoke `writing-plans` after brainstorming completes — never jump to code

## Design Principles

Break systems into single-purpose units with well-defined interfaces that can be understood and tested independently.
